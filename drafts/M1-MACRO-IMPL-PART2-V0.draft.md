# M1-MACRO Implementation Spec — Part 2: 推定とソルバー(案 v0)

- 状態: DRAFT(Claude、2026-10-17)。むすびの監査待ち。
- 前提(すべて Freeze 済み): M1-MACRO-MODEL-PART1/2A/2B/2C/2D/2E-V1、M1-MACRO-TRANSFORM-PART1/2A/2B-V1、M1-MACRO-IMPL-PART1-V1、EVAL-SPEC-V1、S0(参照実装 v1.1)
- 封印: 実データの β、μ、損失の値、成績は見ていない。この文書の数値の試験(§12)は、**乱数で作った合成データだけ**で行った。
- 役割: Freeze 済みの β* の定義を、決定的に計算できる数値の手続きにする。**目的関数、重み、同点の規則、warm-up は変えない。** ソルバー、許容誤差、上限回数などの定数は、ここで値を固定する。成績を見て選ばない(§11)。

## 1. 計算する量(Freeze 済みの定義の再掲)

Horizon h、Origin t について(Model 2-A・2-B・2-C・2-D):

- 群 g = (p, i)。i ∈ E_{t,h}、p ∈ P_i。群ごとに、S0 が Origin i で発行した pool {Z_gj}(j = 1..N_g)、σ_g = σ_M0,p,i、実現値 y_g、特徴量の行 x_g がある。
  - x_g = (F_US, F_JP, F_POS)(USDJPY)、x_g = (0, F_JP, F_POS)(CHFJPY・INRJPY)。β = (β_US, β_JP, β_POS) は3つのペアで共有する(Transformation 2-B)。
- 重み ω_g = 1 / (|E_{t,h}| · |P_i|)。Σ_g ω_g = 1。
- J_{t,h}(β) = Σ_g ω_g · CRPS_g(β) / σ_g(Model 2-A §3.1 の CRPS)。
- warm-up: |E_{t,h}| ≥ 250 のときだけ推定する(Model 2-D)。
- β*_{t,h} = argmin { ‖β‖₂ : β ∈ argmin J_{t,h} }(Model 2-C §5)。

## 2. 数値問題への落とし方

### 2.1 β に依存する部分

Model 2-A §3.1 のとおり、CRPS の第2項は β によらない。群 g の折れ点を

a_gj = y_g − σ_g · Z_gj(y の空間)

とし、昇順に並べたものを a_g(1) ≤ … ≤ a_g(N_g)、累積和を S_g(k) = a_g(1) + … + a_g(k)(S_g(0) = 0)、合計を T_g = S_g(N_g) とする。μ = x_g·β について、

G_g(μ) = (1 / (N_g σ_g)) Σ_j |μ − a_gj|

が CRPS_g / σ_g のうち β に依存する部分である。最適化するのは Φ(β) = Σ_g ω_g G_g(x_g·β)(J から定数を除いたもの)。argmin は J と同じ。

### 2.2 1次の部分(piece)

G_g は凸で区分的に1次である。k = 0..N_g について

ℓ_gk(μ) = ((2k − N_g) μ + T_g − 2 S_g(k)) / (N_g σ_g)

とすると、**G_g(μ) = max_k ℓ_gk(μ)** が成り立つ(各 ℓ_gk は G_g の支持直線)。μ での値を与える k は k_g(μ) = #{j : a_gj ≤ μ}。

### 2.3 集約した piece は、Φ の大域的な下界

点 β_r で各群の k_g(x_g·β_r) を選び、足した1次関数

L_r(β) = Σ_g ω_g ℓ_{g, k_g(x_g·β_r)}(x_g·β) = s_r·β + c_r

は、β_r で Φ と一致し(Φ(β_r) = L_r(β_r))、**すべての β で Φ(β) ≥ L_r(β)**(各項が下界のため)。したがって、L_r をいくつ集めても、その最大値の最小値は Φ の最小値の**証明つきの下界**になる。§5 の大域最適の確認はこの性質だけに依る。

## 3. 入力の数値表現

| 量 | 表現 | 決め方 |
|---|---|---|
| F_US、F_JP | IEEE 754 binary64 | Impl Part 1 の Decimal の差を、正しく丸める変換(Python の float(Decimal))で1回だけ binary64 にする |
| F_POS | binary64 | 建玉は整数として読み、float(Long − Short) / float(Total_OI)。分子・分母は 2^53 未満なので正確に表せ、割り算1回だけで丸める(Decimal を経由しない。2回の丸めを避けるため) |
| Z_gj、σ_g | binary64 | S0 の発行値(参照実装 v1.1 は 17 桁の文字列で書き出す)を float() で読む。往復で同じビットに戻る |
| y_g | binary64 | ORIGIN_TARGET_MAP_V1 と Freeze 済みの評価のコードが定める値をそのまま使う。M1-MACRO で計算し直さない |
| a_gj | binary64 | y_g − σ_g · Z_gj を、乗算1回・減算1回の順に計算する(融合積和 FMA を使わない) |
| S_g(k) | binary64 | 昇順に並べた a_g を、左から右へ逐次に足す(pairwise 和や BLAS を使わない) |

- 特徴量の尺度を変える、中心を引く、列を正規化するなどの前処理(数値の条件をよくするためのものを含む)はしない。ソルバー内部の自動の尺度調整は、§9 の固定した設定のまま使う。
- 内積 x_g·β は、3つの積を math.fsum で足す(行列ベクトル積の BLAS を使わない。CPU によって足し算の順序が変わるのを避けるため)。
- Φ の値と s_r、c_r の各成分は、群についての和を math.fsum で計算する(正しく丸めた和なので、足す順序によらない)。

## 4. 第1段: Φ の最小値を求める(下界つきの cutting-plane 法)

アルゴリズム(level 型の安定化をつけた Kelley の方法。乱数を使わない):

1. 初期点 β_0 = 0(S0 と同じ点)。箱 |β_k| ≤ B の中で解く。
2. 反復 r = 0, 1, 2, … で:
   - Φ(β_r) を計算し(上界 UB = これまでの最小の Φ。その点を β̂ とする)、集約した piece L_r を加える。
   - 線形計画 LB = min θ s.t. θ ≥ L_q(β)(q ≤ r)、|β_k| ≤ B を解く(変数は β と θ の4つ以下)。LB は §2.3 により証明つきの下界。
   - UB − LB ≤ τ_J なら終了。
   - そうでなければ、次の点を level の射影で決める: level = LB + λ_lev (UB − LB) として、max_q L_q(β) ≤ level を満たす β のうち、‖β − β̂‖_∞ が最小のもの(線形計画)。
3. 出力: β̂(UB を与えた点)、UB、LB、反復の数、終了の理由。

箱 B について: B は解を制限するためのものではなく、最初の数回の線形計画を有界にするための数値の装置である。**終了した β̂ が、0 でない列(その座標に 0 でない x_g が少なくとも1つある)の座標で箱の境界に触れていたら、失敗(§8、BOX_ACTIVE)とする。** 箱で切った値を発行することはしない。

すべての群で x の列が 0 の座標(たとえば E_{t,h} に USDJPY の群が1つもない場合の β_US)では、Φ はその座標によらない。その座標の値は第2段で 0 に決まる(最小ノルム)。

## 5. 大域最適の確認

Φ は凸なので、局所的な最小は大域的な最小である。確認の基準は次の1つにする。

**UB − LB ≤ τ_J**(UB は β̂ での Φ の正確な評価、LB は §2.3 の下界の線形計画の値)

- この差は、β̂ が「最小値から τ_J 以内」であることの証明になる。初期点や反復の経路に依らない。
- LB は線形計画のソルバーの許容誤差(§9、10⁻¹⁰)の範囲で正確である。τ_J はそれより十分大きくとる(§7)。
- 報告する J*(定数項を含む CRPS の値)は、UB に Model 2-A の第2項の加重和を足したもの。**この値は学習データ上の損失なので、封印の対象とする**(§11)。

## 6. 第2段: 同点の規則(最小ノルム)

Model 2-C §5 の β* = argmin { ‖β‖₂ : β ∈ argmin Φ } を、次のように計算する。

1. 範囲: K = { β : Φ(β) ≤ UB }。β̂ は K に入る(Φ(β̂) = UB)。K は argmin Φ を含み、§5 により { Φ ≤ min Φ + τ_J } に含まれる。**目標の値を UB より上げない**(Φ を悪化させて β を縮める余地を、確認済みの最適の許容誤差の中だけに閉じ込める)。
2. 外側からの近似: 第1段で集めた piece から、K を外側から近似する多面体 K̃ = { β : L_q(β) ≤ UB(すべての q)} を作り、2次計画 β₂ = argmin { ‖β‖₂² : β ∈ K̃ } を解く(変数は β の3つ以下)。
3. 確認: Φ(β₂) ≤ UB + τ_2 なら β* = β₂ として終了。そうでなければ、β₂ での集約した piece を加えて 2 に戻る(K̃ は単調に縮み、piece の数は有限なので、有限回で終わる)。
4. 上限の回数を超えたら失敗(§8、TIEBREAK_NOT_CONVERGED)。β̂ で代用しない。

帰結(明記する): 最小値をとる β が1点だけの場合も、第2段は K の中の最小ノルムの点を返すので、β* は β̂ からわずかにずれうる。ずれは K の大きさで抑えられる(Φ の最小値の近くでの曲がり方からの粗い見積もりで、β で 10⁻⁶ 程度。§11 の合成データの試験で確かめる)。これは Model 2-C §5.4 の「許容誤差の中で判定する」ことの具体的な形で、経済的・統計的な縮小ではない。

## 7. 固定する定数

| 定数 | 値 | 理由(すべて数値の精度から。データの値や成績は使っていない) |
|---|---|---|
| τ_J(第1段の最適の許容誤差、J の単位) | 1 × 10⁻⁸ | J は O(1)(CRPS / σ、Σω = 1)。線形計画の許容誤差 10⁻¹⁰ による下界の誤差より2桁大きい。合成データ(§12)で、10⁻⁹ では level の方法が許容誤差の手前で止まる例があったので、10⁻⁸ にした |
| τ_2(第2段の確認の許容誤差) | 1 × 10⁻¹⁰ | 線形計画・2次計画のソルバーの許容誤差と同じ桁 |
| λ_lev(level の割合) | 0.3 | level 型の方法の通常の範囲(0 と 1 の間)。収束の速さだけに関わり、解の定義には関わらない |
| B(箱) | 10 | β の単位は「特徴量 1 あたりの対数リターン」。F_US = 1 は 100bp の変化なので、|β| = 10 は 100bp で 1000% の動きにあたり、意味のある解の範囲より十分大きい。境界に触れたら失敗(§4) |
| 第1段の反復の上限 | 2000 | 合成データでは 40 回前後で終わった |
| 第2段の反復の上限 | 200 | |
| ソルバーの許容誤差 | primal・dual の feasibility とも 1 × 10⁻¹⁰ | |

これらの値は、この文書の Freeze で固定する。実装の Freeze までに変えてよいのは、§12 の合成データの試験で数値上の理由(収束しない、許容誤差を満たせない)が示された場合だけで、その場合も新しい版の文書としてむすびの監査を受ける。実データでの係数・損失・成績を理由に変えることは禁止する。

## 8. 失敗の扱い

次のどれかが起きたら、その (t, h) の推定は失敗とする。

| subreason | 条件 |
|---|---|
| SOLVER_STATUS | ソルバーが最適以外の状態を返した(実行不能、非有界、数値の問題など) |
| GAP_NOT_REACHED | 第1段の上限の回数までに UB − LB ≤ τ_J にならなかった |
| BOX_ACTIVE | §4 の箱の境界に触れた |
| TIEBREAK_NOT_CONVERGED | 第2段が上限の回数までに終わらなかった |
| NONFINITE | 入力または途中の値に NaN・無限大がある |

失敗したとき:

- その (t, h) のすべてのペアについて、Decision_Class = ABSTAIN_SYSTEM、Reason_Code = SOLVER_FAILURE(subreason を記録)、Parameter_State = ESTIMATION_FAILED。
- **代わりの値で予測を出さない。** 前の Origin の β、β = 0(親の S0 の予測)、箱で切った値、第1段の β̂ のどれも使わない(Model 2-D §2 の、親の予測に切り替えない規則と同じ考え方)。
- 次の Origin では、最初から解き直す(§9)。
- 失敗の件数と subreason は、成績ではないので、実装の検査で見てよい。

## 9. 決定性

- **各 (t, h) を最初から解く。** 前の Origin の β や piece を初期値に使わない(warm start をしない)。β*_{t,h} は、E_{t,h} の入力だけで決まる純粋な関数になり、1つの Origin だけを取り出して再計算できる。
- 群の並べ方: (Origin の日付, ペアの名前の ASCII 順)。piece は生成した順に制約に加える。
- ソルバー: HiGHS(線形計画は双対 simplex、2次計画は HiGHS の 2次計画のソルバー)。Python の highspy の版を実装の Freeze で1つに固定する。設定: threads = 1、random_seed = 0、presolve = on、§7 の許容誤差。その他は既定の値のまま固定する。
- 環境: Python、numpy、highspy の版と、実行するコンテナのイメージ(digest)を実装の Freeze で固定する。BLAS を使う演算は、推定と予測の計算に使わない(§3)。並列の計算(OMP_NUM_THREADS など)は 1 にする。
- **同じ環境・同じ種類の CPU では、β* は同じビットになることを求める。** CPU や環境が違う場合はビットの一致を保証できないので、§10 の許容誤差の中での一致を求める。台帳に発行した値が正式な記録であり、再計算は照合だけに使う(Part 4)。
- 群ごとの並べ替えと累積和は Origin t によらない(群の pool は発行時に決まっている)ので、Origin の間で保存して使い回してよい。ただし使い回した値と計算し直した値はビットで一致しなければならない。

## 10. 独立の実装と照合

- Claude が、本番の実装とは別に書いたコードで β* を計算する。下界の作り方は本番と違う方法にする: 群ごとの epigraph の線形計画(各群に変数 t_g を置き、t_g ≥ ℓ_gk の制約を必要なものだけ加えていく方法)。群の数が多くて時間がかかる 1D では、本番と同じ集約した piece の方法を、別に書いたコードで使ってよい。
- 照合の基準(すべて満たすこと):
  1. 両方の実装で §5 の確認(UB − LB ≤ τ_J)が通る。
  2. |UB_A − UB_B| ≤ τ_J。
  3. ‖β*_A − β*_B‖_∞ ≤ 1 × 10⁻⁴。
  4. その Origin で予測するすべてのペアについて、|μ_A − μ_B| ≤ 10⁻³ · σ_M0。
- 3・4 が満たされず 1・2 が満たされる場合は、Φ がほぼ平らな方向がある可能性がある。照合は失敗とし、原因を調べる(実装の Freeze の前に解決する)。
- 照合は実装の Freeze の前に行う。そのときに見てよい結果は §11 のとおり。

## 11. 封印との関係(実装の検査で見てよいもの)

Impl Part 1 §9 の境界をそのまま使う。β、μ、J* は**封印したまま**にする。そのうえで、ソルバーを検査するために次の2段を設ける。

1. **合成データの試験(実装の Freeze の前に必須)**: 乱数で作ったデータ(実データと同じ大きさ: 群の数 最大 12000、pool の大きさ 最大 6000 など)と、答えが分かっている小さな例で、すべての結果(β、J、収束)を見て検査する。実データを含まないので封印に触れない。
   - 答えが分かっている例: すべての特徴量が 0(β* = 0、S0 と一致)。1次元の場合(重み付きの中央値として正確に解ける)。ある列がすべて 0(その β が 0)。最小値が1点に決まらないように作った例(最小ノルムの点が手で計算できるもの)。小さな例では、すべての piece を入れた線形計画(全展開)の解と比べる。
2. **実データでの盲検の実行(実装の Freeze の前、任意)**: 実データで、本番と独立の実装を両方走らせる。**出力するのは、各 (t, h) の終了の状態、反復の数、UB − LB、§10 の照合の結果(差の大きさと合否)、失敗の subreason だけ**とし、β、μ、J*、損失の値は表示も保存もしない。この結果を見て変えてよいのは、数値の問題(収束しない、照合が合わない)の修正だけで、§7 の手続きに従う。

むすびと純さんに判断してほしい点: 2 の盲検の実行を、実装の Freeze の前に行ってよいか(§13)。

## 12. 合成データの試験の結果(参考。実データは使っていない)

この案を作る前に、この作業環境(scipy 1.18.1 に含まれる HiGHS)で合成データを使って確かめた。乱数のデータ: 3次元、群の 1/3 だけ第1列が 0 でない(USDJPY の構造をまねたもの)、Z は自由度 5 の t 分布。

| 群の数 | pool の大きさ | 第1段の反復(τ = 10⁻⁹ での試行) | 時間 |
|---|---|---|---|
| 250 | 800 | 38〜42(4回のうち1回は 3000 回で止まり、差 1.1 × 10⁻⁹) | 0.1 秒 |
| 800 | 1400 | 39〜41(4回のうち1回は 3000 回で止まり、差 4.5 × 10⁻⁹) | 0.2 秒 |
| 4000 | 3000 | 37〜44 | 0.8 秒 |
| 12000 | 6000 | 36〜42 | 4 秒 |

- τ = 10⁻⁹ では 16 回中 2 回、level の方法が許容誤差の手前で止まった(下界の線形計画の精度による)。§7 で τ_J = 10⁻⁸ にしたのはこのため。10⁻⁸ ならこの 16 回はすべて通る。
- 群ごとの epigraph の線形計画で仕上げる方法も試した。小さな問題では差が 10⁻¹⁶ まで縮んだが、群の数 12000 では 10 分以内に終わらなかった。本番の方法にしなかったのはこのため(§10 の独立の実装では、群の数が少ない 1W・4W で使う)。
- 1D の過去の再生(約 3700 の Origin)は、この速さなら数時間の見込み。
- 第2段(2次計画)はこの作業環境では試していない(2次計画のソルバーがない)。実装の Freeze の前の合成データの試験(§11 の 1)で確かめる。

## 13. 採らない案

| 案 | 採らない理由 |
|---|---|
| すべての折れ点を展開した線形計画(重み付き LAD の標準形) | 1D では行の数が数千万になり、Origin ごとに解くと現実的でない。小さな問題の検査(§11)では使う |
| 群ごとの epigraph の線形計画を本番にする | 正確だが、群の数 12000 で遅すぎた(§12) |
| 内点法だけ、IRLS、平滑化した近似 | 頂点の解にならず、§5 の下界つきの確認と組み合わせにくい。近似の誤差の扱いが別に要る |
| 確率的な勾配法など | 乱数を使い、決定的でない(Model 2-A §4 で禁止) |
| 小さな L2 の罰則で最小ノルムを近似する(exact regularization) | 理論上は十分小さな罰則で正確になるが、その大きさを確かめる手段がなく、正則化と区別しにくい(Model 2-C で λ = 0) |
| 前の Origin の β から始める(warm start) | 速くなるが、β が経路に依存する。§9 の「1つの Origin だけで再計算できる」性質を失う |
