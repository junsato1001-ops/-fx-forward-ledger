## 4. 再構築の方法と、その限界

### FOMC

- 予定: 1999年分と 2002〜2027年分の「翌年の予定(tentative schedule)」の発表から取った(全26件、2009年以降は公表時刻つき)。
- 変更: 次の告知から取った。
  - 2005-09-09、2006-02-08、2006-07-20、2008-11-20、2009-02-13、2012-05-16(延長・短縮)
  - 2011年9月の延長: 発表が見つからないため、8月会合の議事録の公表時刻(2011-08-30 14:00 ET)を最初の公表とした。保守的な扱い
  - 2020-03-15 の取りやめ
- 臨時会合と電話会議: 事前の告知がない限り、開催日が終わった後に「あった」と分かるものとした(規則 R2)。2020年3月の2回は、声明の公表時刻を最初の公表とした。

### 日銀

1. 公表の規則は、一次資料で途切れずにたどれた。
   - 1997-12-26: 各四半期末に、翌月以降6か月分を公表
   - 2000-09-08: 3・6・9・12月に6か月分を公表(実態の確認)
   - 2007-06-08: 6・12月の会合で、1年分を公表
   - 2015-06-19: 2016年から年8回
   - 2015-08-07 以降: 毎年の日程表
2. RULE_RECONSTRUCTED は、会合の**直前の**規則上の公表(その月の末日を公表日とみなす)の時点から、実際の日付が予定として知られていたとみなす。それより前の公表には、その会合を含めない。
3. **重要な発見**: 2011年2月の会合は、2010-10-28 の告知に付いた表では 16・17日で、実際は 14・15日だった。変更の告知は見つからない。日銀は、通常の日程の公表の際に、告知なしで日付を変えることがあったと考えられる。
   - これは RULE_RECONSTRUCTED の前提(実際の日付 = 公表された日付)が崩れうることを示す。
   - 規則の期間で、告知に付いた表と突き合わせられたのは、1998年前半、2000年後半、2001年4〜9月、2009〜2012年の一部だけ。それ以外の期間で、告知のない日付の変更や、招集の告知のない臨時会合があっても、検出できない(2011-11-30 は表と突き合わせられたので見つかった)。
   - したがって、RULE_RECONSTRUCTED を DIRECT_SOURCE と同じ証拠の強さで扱わない(むすびの条件どおり)。特徴量の設計では、RULE の期間を外す、または感度分析で分けるなどの扱いを、Transformation Spec で決める必要がある。
4. 古い日程表(1997年、2000年、2001年)は、セルの構造が不規則なので、会合日の列だけを手で書き起こした(event log の Note に記載)。

## 5. 補足と確認事項

- 作業用ブランチ `gate-work`(FRB・日銀のページの抜粋)は、main に監査情報が残っていることを読み直して確認した後に削除した(むすび承認)。
  - main に残したもの: event log、取得ページの一覧(URL・SHA-256・取得時刻・抽出プログラムの commit)、生成プログラム、Gate の結果。
  - 将来の監査の経路: 公式 URL を取り直す → SHA-256 を比べる → `tools/gate/extract_pages.py` で抜き出す → `tools/gate/calendar_build.py` を実行する → event log を比べる。公式ページが変わっていて SHA-256 が一致しない場合は、その事実を記録する。
  - 注意: ブランチを削除しても、push 済みの commit やオブジェクトが GitHub から直ちに完全に消える保証はない。目的は「正式な main に作業用の抜粋を残さない」ことである。
- 告知の多くは時刻が分からないため、公表日の翌日の T_info から使う保守的な規則になっている。
- 2026年10月以降の会合は予定だけで、実際の開催との突き合わせはしていない。
