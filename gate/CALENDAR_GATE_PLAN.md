- 封印: 会合の日付と告知の日付だけを扱う。金利・価格・成績は扱わない(Performance Seal INTACT)。

## 2. event log の形式(むすびの推奨を採用)

`Central_Bank, Announcement_Date, Announcement_Time(あれば), Old_Meeting_Date, New_Meeting_Date, Event_Type, Source_URL, Source_SHA256`

Event_Type の案:

- `SCHEDULE_ANNOUNCED`(予定の公表。会合ごとに1行)
- `SCHEDULE_CHANGED`(日付の変更)
- `MEETING_EXTENDED`(1日から2日へ。決定の日が変わる)
- `UNSCHEDULED_MEETING`
- `CONFERENCE_CALL`
- `MEETING_CANCELLED`

FOMC の「決定の日」は会合の最終日とし、両方の日付を残す。

## 3. 各 Origin の T_info で、日程をどう再構築するか(確認してほしい規則)

1. **公表日が分かる告知**: 公表日時が T_info 以前のものだけを使う。時刻が分からない告知は、**公表日の翌日の T_info から**使う(Matrix §2 C7)。
2. **臨時会合・電話会議**: 事前の告知が残っていない限り、**開催日の翌日の T_info から**「あった」と分かるものとする。開催前に知っていたことにはしない。
3. **日銀の2014年以前で、日程表そのものが残っていない期間**: 「公表の規則」で代える。
   - 2007年6月以降は、6月と12月の会合の最終日に、その後12か月分の日程が公表されたとみなす。
   - それ以前は、3・6・9・12月の会合の最終日に、6か月分の日程が公表されたとみなす。
   - 日付は実際の開催日を使い、変更の告知がある会合だけ、告知より前は変更前の日付に戻す。
4. **突き合わせ(漏れの検出)**: 再構築した「各時点の日程」と、実際の開催記録を全件突き合わせる。告知で説明できない食い違いが1件でもあれば GAP として記録する。GAP の期間は、日程の特徴量を MODEL_PREREQ_UNAVAILABLE にする(推測で埋めない)。
   - 例: 予定にない会合が開かれたが、臨時会合の記録がない場合。
   - 例: 予定と実際の日付が違うが、変更の告知がない場合。
5. **再構築できる最古の時点**: 一次資料で公表の規則と告知が確認できる最古の時点まで遡る。
   - 日銀: 現行の日銀法の下の決定会合は 1998年4月から。それより前は、資料が見つかるかで決める。
   - FOMC: 1999年(ECB の価格と揃える)以前は、boarddocs の告知が揃うかで決める。

## 4. この計画で確認してほしいこと

- §3 の 1〜4 の規則。特に「日銀の 2014年以前は公表の規則で代える」でよいか。この方法では、実際の開催日を変更前の日付に戻せるのは、変更の告知が残っている会合だけになる。告知のない変更が実際にあった場合、日程表が残っていない期間では元の予定日が分からないので、§3-4 の突き合わせでも**検出できない**(この方法の限界。日程が公表されていた事実と、告知の一覧が完全であることに依存する)。
- 電話会議を event log に残すか(特徴量として使うかは Transformation Spec で決める。log には残しておくことを推奨)。
