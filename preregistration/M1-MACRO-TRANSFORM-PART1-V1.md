## 0. 設計の方針

1. **特徴量は少なくする**。検出力の分析(M0→S0 程度の改善でも、確かめるには数十年の Forward が必要)から、特徴量を1つ増やすごとに検定の力が落ちる。V1 は3つ以下を目標にする。
2. **変換は1通りに決める**。複数の案を残す場合は、すべて Freeze して別の仮説(別 Trial)として扱う。この文書では各特徴量に1つの変換だけを置く。
3. **データから決める尺度を使わない**。標準化の窓や外れ値の閾値のようにデータを見て決めがちな量は、使わない(標準化なし、切り捨てなし)。尺度は固定の単位(bp、比率)だけにする。過去の窓の取り方による look-ahead と、研究者の選択の余地を同時に減らすため。
4. **通貨ペアに一般化できる形にする**。封印中のホールドアウト(GBPJPY・AUDJPY・CADJPY・SGDJPY・KRWJPY)で後に検証するので、特徴量は「円の側」と「相手通貨の側」に分ける。相手通貨の側で V1 が持っているのは米ドルの系列だけである。

## 2. 変換(raw → feature)

### F_US: 米国2年金利の変化(米ドル側)

- 定義: `F_US(D) = ( y_US2(v) − y_US2(v − 20) ) / 100bp`(切り捨てなし)
- v: Origin D で使ってよい最新の値の日付(Matrix §2: D−1(暦日)より前の、米国の最後の公表営業日)
- v − 20: 米国債の公表営業日で 20日前
- 単位: bp を 100bp で割った無次元量(50bp → 0.5、200bp → 2.0)

### F_JP: 日本2年金利の変化(円側)

- 定義: `F_JP(D) = ( y_JP2(u) − y_JP2(u − 20) ) / 100bp`(切り捨てなし)
- u: Origin D で使ってよい最新の値の日付(Matrix §2: 2営業日遅れ)
- u − 20: 財務省の公表営業日で 20日前

### F_POS: 投機筋の円ポジションの偏り(円側)

- 定義: `F_POS(D) = ( LeveragedFunds_Long − LeveragedFunds_Short ) / Total_Open_Interest`
  - 対象: CFTC TFF の JAPANESE YEN(097741)、Futures Only
  - 使う報告: 公表時刻の上限(Matrix §3 と CFTC Gate)が T_info 以前のうち、最新のもの
- 分母: その市場の**総建玉**(Total Open Interest)。カテゴリー内の gross(Long+Short)ではない。意味は「Leveraged Funds のネットの円ポジションが、市場全体の建玉に対してどれだけ偏っているか」
- **Spreading**(同じトレーダーが持つ、打ち消し合う買いと売り)は**分子に含めない**。Long と Short に配分しない
- 総建玉が 0 または欠けている報告は、F_POS を欠測とする(構造的な欠測)
- 範囲を仮定しない。モデルの設計は F_POS の範囲に依存しない
  - 参考: CFTC の解説では、Nonreportable は総建玉から報告義務のある建玉の合計を引いて算出する。そうなら Leveraged Funds の Long と Short はそれぞれ総建玉を超えない。ただし値で確かめることはしない(封印)
- 符号: 正 = Leveraged Funds が円先物を買い越し(円高の側に偏っている)
- 列名(Leveraged Funds の Long・Short と、総建玉)は、実装の前に年次ファイルの**見出しだけ**で確かめて固定する。見出しは値ではないので封印の対象外
- **CFTC のカテゴリー**: M1-MACRO-V1 の事前の仮説を、レバレッジを使う主体の方向性のあるポジションと、その巻き戻しの圧力に限定する。Asset Manager、Dealer、Other Reportables との比較は行わない。Asset Manager は V1 では一切試さない(将来使うなら別 Trial)
- **利用開始**: F_POS feature availability start = Origin 2010-12-08(CFTC Gate)。それより前の Origin でモデル全体をどうするかは Part 2 で決める

### 金利の差ではなく、日米を分ける理由

米日の金利差を1つの特徴量にすると、米ドル円にしか意味がない。日米を分ければ、F_JP は円のすべてのクロスに使え、F_US は米ドルが入るペアにだけ使える。特徴量の数は1つ増えるが、ホールドアウトでの検証に必要な一般化を優先する。どのペアにどの特徴量を入れるか、ペアの間で係数を共有するかは、Part 2 の Pair/Horizon の割り当てで決める。

### 水準ではなく変化を使う理由(金利)

- 2年金利の水準には、政策金利の局面(日本のゼロ金利、2022年以降の米国の急な利上げ)による強い非定常性がある。水準を標準化するには窓を決める必要があり、窓の選択が結果を左右する。
- 変化は事前設計の C2(政策期待の変化)のメカニズムに直接対応する。
- キャリー(金利差の水準)の仮説は V1 では検証しない。必要なら別 Trial にする。

## 3. point-in-time の変換で固定する値

| 項目 | 値 | 理由 |
|---|---|---|
| 変化の期間 | 20 source-business-days(金利の両方) | 約1か月。主な予測期間(1W・4W)に合わせ、1D 専用の短い期間は作らない(Horizon ごとに変えると自由度が増える) |
| 尺度 | 固定 100bp(単位の換算) | データから決める標準化の窓を使わない。ゼロ金利の時期に、変動の小ささで割って値が過大になる問題も避けられる |
| 外れ値 | **切り捨て・winsorize はしない** | 切り捨ては「極端な変化には追加の情報がない」という仮説を暗黙に入れる非線形の選択で、閾値の根拠を値を見ずに示せない。外れ値への頑健性が必要なら、Model Spec の正則化で扱う |
| 最低履歴数 | 20日前の値があること(各系列の公表営業日で) | 変化の定義に必要な最小限 |
| 標準化(平均を引く等) | しない | 平均をデータから推定しない。中心をどこに置くかは Model Spec の係数推定(切片)に任せる |
| CFTC の尺度 | なし(総建玉に対する比率) | もともと無次元。範囲は仮定しない |
| Horizon ごとの変換 | なし | すべての Horizon で同じ変換を使う |

各系列の欠測と古さの扱い(STALE、ABSTAIN_SYSTEM、PREREQ_UNAVAILABLE)は、Matrix V1 §5 のとおり。ある特徴量が欠けたときにモデル全体をどうするかは、Part 2 の missing-feature policy で決める。

**1点の確認**: 20日前の値の日付は、各系列の公表営業日で数える。米国と日本で日付がずれる(米国は D−1 より前の最後の営業日、日本は2営業日前)。2つの特徴量は別々の特徴量なので、日付を揃える必要はない。それぞれが point-in-time で正しければよい。
