## 1. 計算する量(Freeze 済みの定義の再掲)

Horizon h、Origin t について(Model 2-A・2-B・2-C・2-D):

- 群 g = (p, i)。i ∈ E_{t,h}、p ∈ P_i。群ごとに、S0 が Origin i で発行した pool {Z_gj}(j = 1..N_g)、σ_g = σ_M0,p,i、実現値 y_g、特徴量の行 x_g がある。
  - x_g = (F_US, F_JP, F_POS)(USDJPY)、x_g = (0, F_JP, F_POS)(CHFJPY・INRJPY)。β = (β_US, β_JP, β_POS) は3つのペアで共有する(Transformation 2-B)。
- 重み ω_g = 1 / (|E_{t,h}| · |P_i|)。Σ_g ω_g = 1。
- J_{t,h}(β) = Σ_g ω_g · CRPS_g(β) / σ_g(Model 2-A §3.1 の CRPS)。
- warm-up: |E_{t,h}| ≥ 250 のときだけ推定する(Model 2-D)。
- β*_{t,h} = argmin { ‖β‖₂ : β ∈ argmin J_{t,h} }(Model 2-C §5)。

## 2. 数値問題への落とし方

### 2.1 β に依存する部分

Model 2-A §3.1 のとおり、CRPS の第2項は β によらない。群 g の折れ点を

a_gj = y_g − σ_g · Z_gj(y の空間)

とし、昇順に並べたものを a_g(1) ≤ … ≤ a_g(N_g)、累積和を S_g(k) = a_g(1) + … + a_g(k)(S_g(0) = 0)、合計を T_g = S_g(N_g) とする。μ = x_g·β について、

G_g(μ) = (1 / (N_g σ_g)) Σ_j |μ − a_gj|

が CRPS_g / σ_g のうち β に依存する部分である。最適化するのは Φ(β) = Σ_g ω_g G_g(x_g·β)(J から定数を除いたもの)。argmin は J と同じ。

### 2.2 1次の部分(piece)

G_g は凸で区分的に1次である。k = 0..N_g について

ℓ_gk(μ) = ((2k − N_g) μ + T_g − 2 S_g(k)) / (N_g σ_g)

とすると、**G_g(μ) = max_k ℓ_gk(μ)** が成り立つ(各 ℓ_gk は G_g の支持直線)。μ での値を与える k は k_g(μ) = #{j : a_gj ≤ μ}。

### 2.3 集約した piece は、Φ の大域的な下界

点 β_r で各群の k_g(x_g·β_r) を選び、足した1次関数

L_r(β) = Σ_g ω_g ℓ_{g, k_g(x_g·β_r)}(x_g·β) = s_r·β + c_r

は、β_r で Φ と一致し(Φ(β_r) = L_r(β_r))、**すべての β で Φ(β) ≥ L_r(β)**(各項が下界のため)。したがって、数学的には、L_r をいくつ集めても、その最大値 M(β) = max_r L_r(β) の最小値は Φ の最小値の厳密な下界である。

実装上は、s_r と c_r を浮動小数点で計算するので、L_r は Φ の下界からその丸めの分(§7 の見積もりで 10⁻¹⁵ 程度)だけずれうる。実装上の下界は、この丸めを伴う数値的な証明(certificate)として扱う。§5 では、模型 M の最小値そのものは有理数で厳密に計算する(浮動小数点の線形計画の許容誤差を持ち込まない)。

## 3. 入力の数値表現

| 量 | 表現 | 決め方 |
|---|---|---|
| F_US、F_JP | IEEE 754 binary64 | Impl Part 1 の Decimal の差を、正しく丸める変換(Python の float(Decimal))で1回だけ binary64 にする |
| F_POS | binary64 | 建玉は整数として読み、float(Long − Short) / float(Total_OI)。分子・分母は 2^53 未満なので正確に表せ、割り算1回だけで丸める(Decimal を経由しない。2回の丸めを避けるため) |
| Z_gj、σ_g | binary64 | S0 の発行値(参照実装 v1.1 は 17 桁の文字列で書き出す)を float() で読む。往復で同じビットに戻る |
| y_g | binary64 | ORIGIN_TARGET_MAP_V1 と Freeze 済みの評価のコードが定める値をそのまま使う。M1-MACRO で計算し直さない |
| a_gj | binary64 | y_g − σ_g · Z_gj を、乗算1回・減算1回の順に計算する(融合積和 FMA を使わない) |
| S_g(k) | binary64 | 昇順に並べた a_g を、左から右へ逐次に、補償つきの和(Neumaier の方法)で足す(pairwise 和や BLAS を使わない)。丸めの誤差が足す数によらず小さく保たれる(§7 の ε_tie の根拠) |

- 特徴量の尺度を変える、中心を引く、列を正規化するなどの前処理(数値の条件をよくするためのものを含む)はしない。ソルバー内部の自動の尺度調整は、§9 の固定した設定のまま使う。
- 内積 x_g·β は、3つの積を math.fsum で足す(行列ベクトル積の BLAS を使わない。CPU によって足し算の順序が変わるのを避けるため)。
- Φ の値と s_r、c_r の各成分は、群についての和を math.fsum で計算する(正しく丸めた和なので、足す順序によらない)。

## 4. 第1段: Φ の最小値を求める(cutting-plane 法)

アルゴリズム(level 型の安定化をつけた Kelley の方法。乱数を使わない):

1. 初期点 β_0 = 0(S0 と同じ点)。箱 |β_k| ≤ B の中で解く。
2. 反復 r = 0, 1, 2, … で:
   - その反復で評価する点(初回は β_0、以後は下の2点)で Φ を計算し、集約した piece L を加える。上界 UB = これまでの Φ の最小値、その点を β̂ とする。
   - 模型の最小化 min_β M(β)(箱の中)を、浮動小数点の線形計画(HiGHS)で解き、§5 の方法で有理数で厳密に確かめる。得られる値を LB、その点を β_M とする。
   - |UB − LB| ≤ ε_tie なら終了(§5、§7)。LB > UB + ε_tie なら失敗(§8、CERT_INCONSISTENT)。
   - そうでなければ、次に評価する点を2つ決める: (a) β_M、(b) level の射影: level = LB + λ_lev (UB − LB) として、M(β) ≤ level を満たす β のうち ‖β − β̂‖_∞ が最小のもの(線形計画)。
3. 出力: β̂、UB、LB、β_M、集めた piece、反復の数。

(b) だけの v0 の方法は、合成データで UB − LB が 10⁻⁹ 程度で止まった。(a) の点も加えると、模型の最小の頂点が Φ の頂点に一致するまで進み、差が 0 または 10⁻¹⁴ 以下まで縮んだ(§12)。

箱 B について: B は、最初の数回の線形計画を有界にするための数値の装置である。**B が経済的に十分大きいことを、解が箱の制約を受けていないことの保証には使わない。** その保証は次の検査で行う: 終了時の β*(§6)が、0 でない列(その座標に 0 でない x_g が少なくとも1つある)の座標で箱の境界にあれば、失敗(§8、BOX_ACTIVE)とする。箱で切った値を発行しない。

すべての群で x の列が 0 の座標(たとえば E_{t,h} に USDJPY の群が1つもない場合の β_US)では、Φ はその座標によらない。その座標は第2段で正確に 0 になる(最小ノルム。§12 の例 E)。

## 5. 大域最適の確認(有理数での厳密な確認)

Φ は凸なので、局所的な最小は大域的な最小である。

- **模型の最小値 LB を有理数で厳密に求める。** 浮動小数点の線形計画の解から、制約の満たし方の近い順に候補の制約を選び、(β, θ) の次元(4 以下)の数の制約からなる基底を候補から作る。各基底について、頂点と双対の乗数を有理数(Python の fractions.Fraction。浮動小数点の値は正確に有理数に変換される)で解き、(i) その頂点がすべての制約を満たし、(ii) 乗数がすべて 0 以上であることを、正確に確かめる。最初に確かめられた頂点を模型の最適とする(候補は満たし方の近い順に 8、12、16、24 本まで広げる)。確かめられなければ失敗(§8、EXACT_CERT)。
- これにより、LB は「浮動小数点で計算した係数をもつ模型 M」の最小値として厳密である。Φ の下界としては、§2.3 の係数の丸めだけを伴う。
- **確認の基準: |UB − LB| ≤ ε_tie(両側)。** UB は β̂ での Φ の評価(§3 の fsum)。
  - 数学的には LB ≤ min Φ ≤ UB なので UB − LB ≥ 0 である。実装上は、§2.3 の係数の丸めのため、わずかに負になることがある。−ε_tie 以上の負の値は丸めとして受け入れる。
  - **LB > UB + ε_tie は、下界が上界を上回るという、数学的にありえない状態である。** 正常な同点ではなく確認の不整合として失敗にする(§8、CERT_INCONSISTENT)。値の大きさに関わらず、正常な終了とはしない。
- 報告する J*(定数項を含む CRPS の値)は、UB に Model 2-A の第2項の加重和を足したもの。**この値は学習データ上の損失なので、封印の対象とする**(§11)。

## 6. 第2段: 同点の規則(最小ノルム)

Model 2-C §5 の β* = argmin { ‖β‖₂ : β ∈ argmin Φ } を、損失を悪化させる幅を置かずに計算する。

1. **範囲: F = { β : L_r(β) ≤ LB(すべての r)、箱 }**、LB は §5 で厳密に求めた模型の最小値。F は模型 M の最小値の集合そのもので、**LB より上の値を許す幅を持たない。** 第1段が終わった時点で Φ と模型が最適の付近で一致していれば(|UB − LB| ≤ ε_tie)、argmin Φ の点は F に入る。
2. **最小ノルムの点:** β₂ = argmin { ‖β‖₂² : β ∈ F } を、有理数での primal active-set 法で厳密に解く(変数は β の3つ以下、制約は piece の数 + 箱。初期点は §5 の模型の最適の頂点 β_M で、F に入る)。
3. **確認(両側):** |Φ(β₂) − LB| ≤ ε_tie なら β* = β₂(浮動小数点に丸める)として終了。ε_tie はここで「Φ を計算した値が LB と同じとみなせるか」を判定するだけで、F を広げない。
   - **Φ(β₂) < LB − ε_tie** は、模型(Φ の下界のはず)が Φ を上回るという不整合なので、失敗にする(§8、CERT_INCONSISTENT)。
4. Φ(β₂) > LB + ε_tie の場合(β₂ で模型が Φ より低い)、β₂ での集約した piece を加え、§5 で模型の最適を求め直し(LB と β_M を更新)、2 に戻る。piece の数は有限なので、有限回で終わる。
5. 上限の回数を超えたら失敗(§8、TIEBREAK_NOT_CONVERGED)。β̂ や β_M で代用しない。

帰結(明記する):

- 最小値をとる β が1点だけで、模型が Φ と一致していれば、β* はその点である。合成データの「ほぼ平らだが一意」の例では、損失の差が 5.5 × 10⁻¹⁴ の場合でも、最小ノルムの方向に縮まず、真の最小の点を返した(§12 の例 C)。
- 残る数値の影響は、LB が Φ の最小値より ε_tie 以下だけ低い場合に、F が argmin Φ と一致しないことによるものだけである。その大きさは ε_tie と最適の付近の Φ の曲がり方で決まり、合成データでは β の差で 10⁻⁸ 以下だった(§12 の例 D)。v0 のように、許容誤差を「縮めてよい幅」として使うことはしない。

## 7. 固定する定数

| 定数 | 値 | 理由(すべて数値の精度から。データの値や成績は使っていない) |
|---|---|---|
| ε_tie(数値上の同一の判定。第1段の終了と第2段の確認の両方。両側で使う) | 1 × 10⁻¹³ | Φ は O(1)(CRPS / σ、Σω = 1)。Φ と s_r、c_r は、各項を丸めた後に正しく丸める和(fsum)で計算し、累積和は補償つき(§3)なので、丸めの誤差は 10⁻¹⁵ 程度と見込み、その約 100 倍とした。**これは実証にもとづく技術上の上界であり、厳密な誤差の上界(forward error bound)ではない**(fsum の前の乗算・除算、a_gj、piece の傾きと切片、補償つきの累積和にも丸めがある)。実データと同じ大きさの合成データの試験で余裕を確かめる(§11)。**損失を悪化させてよい幅ではない**(§6) |
| λ_lev(level の割合) | 0.3 | 収束の速さだけに関わり、解の定義には関わらない |
| B(箱) | 10 | 数値の装置(§4)。境界に触れたら失敗 |
| 第5節の候補の制約の数 | 8、12、16、24 の順に広げる | 頂点を決めるのは 4 本以下の制約。合成データではすべて最初の 8 本で確かめられた |
| 第1段の反復の上限 | 3000 | 合成データでは 4〜44 回で終わった |
| 第2段の反復の上限 | 100 | 合成データでは 1〜13 回 |
| 浮動小数点の線形計画の許容誤差 | primal・dual の feasibility とも 1 × 10⁻¹⁰ | 探索の点を決めるためだけに使う。最適の判定には使わない(§5 で有理数で確かめる) |

これらの値は、この文書の Freeze で固定する。実装の Freeze までに変えてよいのは、合成データの試験、または §11 の盲検の実行で、数値上の理由(収束しない、確かめられない、独立の実装と一致しない)が示された場合だけで、その場合も新しい版の文書としてむすびの監査を受ける。実データでの係数・損失・成績を理由に変えることは禁止する。

## 8. 失敗の扱い

次のどれかが起きたら、その (t, h) の推定は失敗とする。

| subreason | 条件 |
|---|---|
| SOLVER_STATUS | 浮動小数点の線形計画が最適以外の状態を返した |
| EXACT_CERT | §5 の有理数での確認で、模型の最適の頂点を確かめられなかった |
| GAP_NOT_REACHED | 第1段の上限の回数までに |UB − LB| ≤ ε_tie にならなかった |
| BOX_ACTIVE | β* が、0 でない列の座標で箱の境界にある(§4) |
| CERT_INCONSISTENT | 確認の不整合: LB > UB + ε_tie(§5)、または Φ(β₂) < LB − ε_tie(§6)。下界が上界を上回るという、数学的にありえない状態 |
| TIEBREAK_NOT_CONVERGED | 第2段が上限の回数までに終わらなかった |
| NONFINITE | 入力または途中の値に NaN・無限大がある |

失敗したとき:

- その (t, h) のすべてのペアについて、Decision_Class = ABSTAIN_SYSTEM、Reason_Code = SOLVER_FAILURE(subreason を記録)、Parameter_State = ESTIMATION_FAILED。
- **代わりの値で予測を出さない。** 前の Origin の β、β = 0(親の S0 の予測)、箱で切った値、β̂、β_M のどれも使わない(Model 2-D §2 の、親の予測に切り替えない規則と同じ考え方)。
- 次の Origin では、最初から解き直す(§9)。
- 失敗の件数と subreason は、成績ではないので、実装の検査で見てよい。

## 9. 決定性

- **各 (t, h) を最初から解く。** 前の Origin の β や piece を初期値に使わない(warm start をしない)。β*_{t,h} は、E_{t,h} の入力だけで決まる純粋な関数になり、1つの Origin だけを取り出して再計算できる。
- 群の並べ方: (Origin の日付, ペアの名前の ASCII 順)。piece は生成した順に制約に加える。
- ソルバー: 浮動小数点の線形計画は HiGHS の双対 simplex(探索の点を決めるためだけ)。最適の確認(§5)と最小ノルム(§6)は、Python の fractions による有理数の計算で行い、浮動小数点のソルバーに依らない。HiGHS(highspy)の版を実装の Freeze で1つに固定する。設定: threads = 1、random_seed = 0、presolve = on、§7 の許容誤差。その他は既定の値のまま固定する。
- 環境: Python、numpy、highspy の版と、実行するコンテナのイメージ(digest)を実装の Freeze で固定する。BLAS を使う演算は、推定と予測の計算に使わない(§3)。並列の計算(OMP_NUM_THREADS など)は 1 にする。
- **同じ環境・同じ種類の CPU では、β* は同じビットになることを求める。** CPU や環境が違う場合はビットの一致を保証できないので、§10 の許容誤差の中での一致を求める。台帳に発行した値が正式な記録であり、再計算は照合だけに使う(Part 4)。
- 群ごとの並べ替えと累積和は Origin t によらない(群の pool は発行時に決まっている)ので、Origin の間で保存して使い回してよい。ただし使い回した値と計算し直した値はビットで一致しなければならない。

## 10. 独立の実装と照合

- Claude が、本番の実装とは別に書いたコードで β* を計算する。群の数が少ない 1W・4W では、下界を群ごとの epigraph の線形計画(各群に変数 t_g を置く方法)という本番と違う方法で作る。群の数が多い 1D では、本番と同じ集約した piece の方法を、別に書いたコードで使ってよい。
- 照合の基準(すべて満たすこと):
  1. 両方の実装で §5 の確認(|UB − LB| ≤ ε_tie)と §6 の確認(|Φ(β₂) − LB| ≤ ε_tie)が通る。
  2. |UB_A − UB_B| ≤ 2 ε_tie。
  3. ‖β*_A − β*_B‖_∞ ≤ 1 × 10⁻⁶。
  4. その Origin で予測するすべてのペアについて、|μ_A − μ_B| ≤ 10⁻⁴ · σ_M0。
- 3・4 は、v0 の値(10⁻⁴、10⁻³ · σ)から厳しくした。第2段が損失の幅を持たなくなったので、2つの正しい実装の差は §6 の帰結の大きさ(合成データで 10⁻⁸ 以下)に収まるはずだからである。
- 1・2 が満たされ 3・4 が満たされない場合は、Φ がほぼ平らな方向がある可能性がある。照合は失敗とし、原因を調べる(実装の Freeze の前に解決する)。

## 11. 封印との関係(実装の検査で見てよいもの)

Impl Part 1 §9 の境界をそのまま使う。β、β の符号、μ、J*、CRPS、M1 と S0 の損失の差、予測、方向の成績、ホールドアウトの成績は**封印したまま**にする。そのうえで、ソルバーを検査するために次の2段を設ける。

1. **合成データの試験(実装の Freeze の前に必須)**: 乱数で作ったデータと、答えが分かっている小さな例で、すべての結果(β、Φ、収束)を見て検査する。実データを含まないので封印に触れない。少なくとも §12 の例 A〜E を、本番の実装で同じ結果になるか確かめ、さらに実データと同じ大きさ(群の数 12000、pool の大きさ 6000)の例で時間と収束を確かめる。
   - **ε_tie の余裕の確認(実装の Freeze の条件)**: 実データと同じ大きさの合成データで、UB − LB、Φ(β₂) − LB、独立の実装との UB の差を記録する。丸めの大きさを表すのは、**負の側の値**(数学的には 0 以上のはずの UB − LB と Φ(β₂) − LB が負になった量)と、独立の実装との差である。これらが ε_tie = 10⁻¹³ に対して十分な余裕(目安として 10 倍以上、つまり 10⁻¹⁴ 以下)にあることを確かめる。正の側の値は、探索を ε_tie で止めた結果として ε_tie 近くまでありうる(§12 の例 D)ので、余裕の判定には使わない。余裕がなければ、成績を見る前なので、§7 の定数を新しい版の文書として監査し直す。
2. **実データでの盲検の実行(実装の Freeze の前。むすびが承認、推奨)**: 実データで、本番と独立の実装を両方走らせる。**出力するのは、各 (t, h) の終了の状態、反復の数、UB − LB、§10 の照合の結果(差の大きさと合否)、失敗の subreason だけ**とし、β、β の符号、μ、J*、損失の値は表示も保存もしない。これは予測の評価ではなく、数値の実装の検証である。
   - この結果を見て変えてよいのは、数値の実装の問題(収束しない、独立の実装と一致しない、許容誤差の上で成り立たない)の修正だけで、§7 の手続きに従う。
   - 「特定の Horizon だけ反復が多いのでモデルを変える」「特定の特徴量を外す」などは禁止する。

## 13. 採らない案

| 案 | 採らない理由 |
|---|---|
| v0 の第2段({ Φ ≤ UB } の中で最小ノルム、UB は最小値から 10⁻⁸ 以内) | 最小値でない β を選んで縮めうる(暗黙の正則化)。むすびの監査で不可 |
| 浮動小数点の線形計画の値だけで最適を判定する | 10⁻¹⁰ より小さい傾きを見落とす(§12) |
| すべての折れ点を展開した線形計画(重み付き LAD の標準形) | 1D では行の数が数千万になる。小さな問題の検査には使う |
| 群ごとの epigraph の線形計画を本番にする | 正確だが、群の数 12000 で遅すぎた(v0 の試験)。1W・4W の独立の実装では使う |
| 内点法だけ、IRLS、平滑化した近似 | 頂点の解にならず、§5 の厳密な確認と組み合わせにくい |
| 確率的な勾配法など | 乱数を使い、決定的でない(Model 2-A §4 で禁止) |
| 小さな L2 の罰則で最小ノルムを近似する(exact regularization) | 十分小さな罰則の大きさを確かめる手段がなく、正則化と区別しにくい(Model 2-C で λ = 0) |
| 前の Origin の β から始める(warm start) | β が経路に依存し、1つの Origin だけで再計算できる性質を失う |
