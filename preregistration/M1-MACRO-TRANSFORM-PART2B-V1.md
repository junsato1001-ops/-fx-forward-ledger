## 0. 前提の確認

- 対象のペアはすべて「円1単位あたりではなく、相手通貨1単位の円建て価格」(XXX/JPY)。y = log(P_End / P_Start) が正なら、相手通貨が円に対して強くなった(円安)ことを意味する。
  - 開発・Forward: USDJPY、CHFJPY、INRJPY
  - 封印中のホールドアウト(RFX-HOLDOUT-A-V1): GBPJPY、AUDJPY、CADJPY、SGDJPY、KRWJPY
- Part 1 の特徴量は、円の側(F_JP、F_POS)と米ドルの側(F_US)に分かれている。V1 は、相手通貨の側の系列を米ドルについてしか持たない。

## 1. どのペアに何を入れるか(N(p))

**規則: 特徴量は、そのペアを構成する通貨の側からだけ入る(通貨の側の原則)。**

| ペア | N(p) |
|---|---|
| USDJPY | { F_US, F_JP, F_POS } |
| CHFJPY、INRJPY | { F_JP, F_POS } |
| GBPJPY、AUDJPY、CADJPY、SGDJPY、KRWJPY(ホールドアウト) | { F_JP, F_POS } |

理由:

- 円の側の特徴量は、円のすべてのクロスに同じ経路(円の動き)で効くと考える。
- F_US は米ドルの側の情報なので、米ドルを含まないペアには入れない。米国の金利が世界的なリスクの経路で他のペアに効く可能性はあるが、それは通貨の側の原則とは別の仮説で、V1 では検証しない。
- N(p) はペアごとに異なってよい(モデルの定義)。Part 2-A により、N(p) の一部が欠けた時期に部分集合で予測することはない。
- 結果として、Part 2-A §3-1 から、**特徴量の側から見た最も早い開始(feature-set availability earliest start)は、すべてのペアで Origin 2010-12-08**(F_POS がすべての N(p) に入るため)。実際の FORECAST の開始は、Model Spec の係数の warm-up の規則によって、これより後ろに動きうる。

## 2. 係数をペアの間で共有するか

**案: 円の側の係数は、すべてのペアで共有する。米ドルの側の係数は USDJPY だけのもの。**

予測の位置のずらし(location shift)を、Horizon h について次の形で表す(係数の推定方法、切片、縮小などは Model Spec で決める)。

- USDJPY: μ_h = β_US,h · F_US + β_JP,h · F_JP + β_POS,h · F_POS
- それ以外の円クロス: μ_h = β_JP,h · F_JP + β_POS,h · F_POS
- β_JP,h と β_POS,h は全ペアで同じ値。β_US,h は USDJPY の機会だけから決まる。

**共有の単位は対数リターン(y の空間)とする。** σ で割った z の空間で共有しない。

- 理由: 円の側の仮説は「円そのものが動く」ことなので、円が x% 動けば、どの XXX/JPY も同じ −x% だけ動く(それに相手通貨の側の動きが加わる)。したがって、効果の大きさはペアの値動きの大きさに比例しない。z の空間で共有すると、値動きの大きいペアほど円の効果が大きいと仮定することになり、通貨の側の原則と合わない。
- 注意: これは Model Spec で「位置のずらしを y の空間で足す」形を事実上決める。Model Spec でこれと異なる形にする場合は、この節と矛盾しないことを示す必要がある。

**推定に使う機会**: 開発・Forward の3ペア(USDJPY、CHFJPY、INRJPY)だけ。ホールドアウトの5ペアは推定に一切使わない(封印)。

- **共同推定**: β_JP,h と β_POS,h は、開発対象の3ペアの対象となる機会(eligible observations)を使った共同推定の共有係数とする。USDJPY の機会も共有の係数の推定に寄与する。β_US,h は、F_US が N(p) に含まれる USDJPY の機会だけから識別される。損失、重み、正則化は Model Spec で決める。
- 1つの推定の中で、USDJPY の機会は3つの特徴量を持ち、他のペアは2つを持つ。F_US は USDJPY 以外のペアでは**モデルの定義上入らない**のであって、欠けているのではない(Part 2-A の補完の禁止には当たらない)。
- 同じ Origin のペアを独立な標本と数えない(EVAL-SPEC-V1 の Origin cluster)。推定の重みの付け方は Model Spec で決める。

**ホールドアウトでの意味**: 円の側の係数を共有しているので、ホールドアウトの5ペアには、3ペアから推定した β_JP,h と β_POS,h をそのまま適用できる。ホールドアウトは「円の側の係数が、推定に使っていない円クロスにも通用するか」の検証になる。

**代わりの案と採らない理由**:

| 案 | 採らない理由 |
|---|---|
| ペアごとに別の係数 | 係数の数が3倍になる。ホールドアウトのペアには係数がなく、適用できない |
| 部分的な共有(階層モデル) | 共有の強さという新しい自由度が加わる。V1 では採らない |
| z の空間で共有 | 上の理由で、通貨の側の原則と合わない |

## 3. Horizon の間で共有するか

**案: 係数は Horizon ごとに別に推定する(Horizon の間で共有しない)。特徴量と変換はすべての Horizon で同じ(Part 1)。対象は 1D・1W・4W のすべて。**

理由:

- **マクロの特徴量による位置の効果が、1D・1W・4W で同じであるという期間構造を、V1 では仮定しない。** 共有するには、たとえば「1セッションあたりの効果が Horizon によらず一定」という仮定が必要になるが、これを値を見ずに正当化する根拠はない。したがって β_·,1D、β_·,1W、β_·,4W を別々に推定する。
- 参考: M1-VOL-SHRINK-V1 も Horizon ごとに推定している。係数は Horizon あたり3つ以下なので、別々に推定しても自由度は小さい。

**1D を対象に含める理由**: EVAL-SPEC-V1 §5.3 で、3つの Horizon(× 2方向 = 6仮説)を確認的な検定の族としてすでに Freeze している。M1-MACRO を設計した後に、1D だけを外して族を変更することはしない。1D を含めるのは「1D に効きそうだから」ではなく、Freeze 済みの評価の族を事後に変えないためである(金利やポジションの効果は、事前設計では主に 1W・4W で考えている)。
