- 状態: **v1 FREEZE CANDIDATE**(Claude、2026-10-17)。v0 に対するむすびの監査(2026-10-17 03:42 JST、CONDITIONAL PASS)の修正を反映した。

  2. 実際に使えるペアだけで平均すること(欠けたペアを 0 として扱わない)と、ペアの数を Origin の中の平均の分母にだけ使うことを明記した(§1)。
  3. 全ペアの観測をまとめて平均する実装を禁止した(§4)。
  4. 拡大していく窓は point-in-time(prequential)に拡大するものであることを明記した(§2)。

- 範囲: 1機会の損失 ℓ_{p,i}(β)(Part 2-A で固定。CRPS / σ_M0)を、推定の目的関数にどう集計するかだけ。損失そのものは変えない。正則化、warm-up、符号の制約は後の段。

## 1. 集計の3つの層

**層1: 機会(ペア)の損失** — Part 2-A のまま、ℓ_{p,i}(β) = CRPS_{p,i}(β) / σ_M0,p,i。ここに重みは掛けない。

**層2: 同じ Origin の中** — Origin i(Horizon h)で推定に使えるペアの集合を P_i とする。

L̄_i(β) = (1 / |P_i|) Σ_{p ∈ P_i} ℓ_{p,i}(β)

ペアは等しい重み。

- **P_i に入っているペアだけを平均する**。P_i に入らないペア(特徴量が欠けた、S0 が予測を出していない、結果が確定していない、σ_M0 が 0 など)の損失を 0 とみなして分母に入れることはしない。
- **|P_i| は、この Origin の中の平均の分母としてだけ使う。** Origin の間の重みには使わない。したがって、使えるペアの数が多い Origin に追加の重みを与えない。

**層3: Origin の間** — Origin t で係数を推定するときに使える過去の Origin の集合を E_{t,h} とする。

J_{t,h}(β) = (1 / |E_{t,h}|) Σ_{i ∈ E_{t,h}} L̄_i(β)

Origin は等しい重み(後の段の正則化の項は、これに加える)。

## 2. 集合の定義

- **P_i**(Origin i で使えるペア): 開発対象の3ペア(USDJPY、CHFJPY、INRJPY)のうち、次をすべて満たすもの。
  - Part 2-A(Transformation)の complete case(N(p) のすべての特徴量がそろう)
  - 親の S0 が FORECAST(Model Part 1 §5)
  - Outcome = OBSERVED
  - σ_M0 が有限かつ > 0(Model Part 2-A §3.2)
- **E_{t,h}**(Origin t で使える過去の Origin): Horizon h の過去の Origin i のうち、
  - Target_End_i ≤ Last_Available_Fix_t(Origin t の時点で結果が確定している)
  - P_i が空でない
- **窓**: E_{t,h} は、上の条件を満たす**すべての**過去の Origin とする(拡大していく窓)。これは全履歴を後から一括で使うことではなく、各 Origin t の時点で結果が確定している過去の Origin だけを使う、point-in-time(prequential)に拡大する窓である(Model Part 1 §4 の Target_End の制約のとおり)。直近の一定期間だけを使う窓や、古い Origin の重みを指数的に下げる減衰は使わない。
- ホールドアウトの5ペアは、どの集合にも入らない(Part 2-B Transformation)。

## 3. 理由

1. **EVAL-SPEC-V1 と同じ単位**。評価は Origin cluster ごとに、そのペアの損失を平均し、Origin を等しい重みで平均する(§5.1)。推定も同じ単位にする。M1-VOL-SHRINK-V1 の QLIKE の集計とも同じ。
2. **同じ Origin のペアを独立な標本と数えない**。円の共通の要因があるので、3ペアそろった Origin を「3標本」と数えると、ペアの数の多い時期が推定を支配する。Origin を等しい重みにすれば、Origin ごとのペアの数が変わっても、時期の重みは変わらない。
3. **σ による重みを二重に掛けない**(むすびの指摘)。σ_M0 で割ることは損失の定義そのもの(Part 2-A)である。層2・層3で σ やペアの値動きの大きさによる重みを追加することは、別の仕様になるので禁止する。
4. **拡大していく窓**。直近の窓の長さや減衰の速さは、新しいパラメータになる。それを値を見ずに決める根拠はない。M1-VOL の v_long も、各ペアの最初からの全履歴を使っている。
   - 帰結(明記する): 構造の変化(たとえば金融政策の局面が変わって、特徴量の効き方が変わる)があっても、古い Origin の重みは下がらない。V1 ではこれを受け入れる。

## 4. 禁止すること

- ペアごとの追加の重み(値動きの大きさ、ペアの重要度、データの長さなどによるもの)
- σ_M0 などによる重みの再適用
- Origin ごとのペアの数による重み(3ペアの Origin を重くするなど)
- **全ペアの観測をまとめた平均**: Σ_i Σ_{p ∈ P_i} ℓ_{p,i} / Σ_i |P_i| の形での実装。§1 の Origin cluster の平均とは、欠けたペアがあると一致しないので、別の仕様になる
- 直近の窓、指数的な減衰、Horizon の重なり(4W の Origin どうしの対象期間の重なり)を理由にした重みの調整
  - 重なりは、実効的な標本数を減らすだけで、目的関数の重みでは扱わない。
  - warm-up で重なりを考慮するかどうか、考慮する場合の定義と閾値は、Warm-up Spec で Freeze する。**M1-VOL の N_param(1D・1W は ×1、4W は ×1/4)を M1-MACRO に自動では引き継がない。** M1-MACRO は係数の数、正則化、閾値が M1-VOL と違うためである。M1-VOL と同じ方法を採る選択肢は残る。

## 5. 推定の手順(確認)

各 Origin t、Horizon h について、E_{t,h} から J_{t,h}(β)(+ 後の段の正則化の項)を最小にする β_{t,h} を求め、Origin t の予測に使う(prequential)。過去に発行した β と予測は書き換えない(immutable)。
